## 1. Что строим

**«Кто Я: Универ Edition»** — офлайн-игра на Android для компании 2–10 человек. В колоде — карточки знакомых людей: друзья группы и преподаватели вуза. Фото — настоящие лица, вырезанные по контуру, с именем и едкими тегами («Доцент кафедры матана, строгий», «Группа ИТ-21, любитель поспать на парах»).

Два режима:

1. **Локальный (один телефон).** Телефон идёт по кругу. Игрок прикладывает его ко лбу, экран смотрит на остальных: они видят, кто он, и подсказывают. Через 10 секунд карточка скрывается, игрок отмечает, угадал он или нет, и передаёт телефон дальше. Когда прошли все — экран «Разбор»: любую карточку можно показать снова, если компания забыла, кого показывала, и итоги.
2. **Онлайн (у каждого свой телефон).** Хост создаёт комнату, получает 6-символьный код, остальные входят по коду и имени. Все одновременно получают синхронный отсчёт 3-2-1 (с вибрацией) и свой персонаж. Игра идёт в одной комнате физически: каждый держит телефон у лба, остальные видят экран. Тап по карточке — скрыть (если пришло уведомление или мимо прошёл преподаватель). В конце — общее раскрытие: кто кем был.

### Ключевые отличия (причина, по которой продукт нужен)

- **Лица знакомых, а не абстрактные «знаменитости».** Смешно ровно потому, что это ваш матан-препод и ваш сосед по общаге. Игра не работает без собственной библиотеки персонажей — поэтому импорт фото и теги сделаны как первоклассная функция, а не «настройки».
- **Телефон во лбу.** Интерфейс держится на трёх вещах: крупный текст, максимальная яркость, звук как единственный канал обратной связи для того, кто ничего не видит.
- **Разбор после круга.** Игра без «а кто это был?» ломается на 4-м игроке. Повторный показ любой карточки — обязательная механика, а не «фича».

## 2. Пользовательские сценарии (проверяй на них каждое решение)

**A — «перемена в универе, 6 человек, один телефон».** Рустам открывает игру, жмёт «Играть на одном телефоне», выбирает пресет «ИТ-21» (6 имён уже сохранены). Игра раздаёт по одному персонажу каждому. Рустам берёт телефон, жмёт «Готово», прикладывает ко лбу. Отсчёт: «Три! Два! Один! Погнали!» — голосом старосты (записан заранее). На экране карточка: красный фон, вырезанное лицо доцента, «Виктор Павлович», теги. Пять человек ржут и подсказывают: «ты у нас пары прогуливаешь». Тики на последних трёх секундах ускоряются, экран гаснет в «Угадал?» — Рустам жмёт «Да», передаёт телефон дальше. После шестого — «Разбор»: сетка из шести карточек, кто-то забыл, кто был третьим, тычут в карточку — она снова показывается на 10 секунд. «Закончить» → итоги: «Угадали 4 из 6, лучший — Аня».

**B — «все со своими телефонами, аудитория 401».** Аня создаёт комнату, код `K7M2QX`, остальные входят по коду и имени. В лобби видно шестерых. Хост жмёт «Начать»: у всех вибрация, у всех одновременно 3-2-1, у каждого свой персонаж. Телефоны подняты, все ржут. У Димы звонит мама — он тапает по карточке, экран становится «Карточка скрыта, нажми, чтобы вернуть». В конце — «Раскрыть всех»: список «Дима — Виктор Павлович, Аня — Лена с кафедры».

**C — «сбор колоды в первый раз».** Пользователь открывает «Персонажи» → «Добавить». Выбирает 12 фото из галереи, для каждого вводит имя и тег, ставит тип. Приложение вырезает лица на устройстве (2–4 с на фото, прогресс виден), показывает превью карточки в реальном времени. Итог — набор из 12 карточек; жмёт «Поделиться набором» → файл уходит в чат группы, друзья импортируют одним тапом.

**D — «фото отвалилось».** Импортированный набор пришёл без двух фото (обрезался мессенджером). Игра не падает: вместо лица — цветной фон с инициалами и подписью «фото не найдено», карточка остаётся играбельной, в библиотеке — бейдж «нет фото».

**E — «связь пропала».** Онлайн-игра, у одного игрока Wi-Fi отвалился на 20 секунд. Он возвращается: комната ещё жива, он видит актуальную фазу (отсчёт/показ/итоги), его персонаж тот же, роль и очки на месте. Если комната истекла — понятный экран «Игра закончилась» + «Создать новую».

**F — «чужой телефон».** Друг дал свой телефон. Игра не требует аккаунта, ничего не грузит из сети (локальный режим вообще без интернета), и в настройках есть «Стереть мои данные» с подтверждением.

## 4. Архитектура

```
┌──────────────────────── приложение (одно APK) ───────────────────────┐
│  ui/            Compose-экраны, только рендер + отправка событий      │
│  game/local/    LocalGameEngine: конечный автомат одного телефона     │
│  game/online/   OnlineGameClient: WS + синхронизация по server time   │
│  game/Deck.kt   детерминированная раздача по seed (общая для режимов) │
│  data/          Room: Character, Player, Preset, Session, Round       │
│                 DataStore: настройки, голосовые пакеты (пути к файлам)│
│  media/         импорт фото → кроп → сегментация → webp-кэш           │
│  audio/         SoundPool + голосовой пак + Android TTS (fallback)    │
└──────────────────────────────────────────────────────────────────────┘
        │ локальный режим: сеть не используется вообще
        │ онлайн: wss://<host>/ws   (JSON, см. 11.2)
        ▼
   Node-сервер комнат (in-memory), держит только: код, имена, фазы,
   seed, отметки «угадал/нет». Ни одного фото. Ни одной картинки.
```

**Инвариант:** результат игры полностью определяется сидом. Сервер раздаёт seed, каждый клиент считает раздачу локально тем же алгоритмом (`Deck.deal(seed, playerCount, deckSize)`), поэтому лица никогда не покидают телефон, а картинки в сети не передаются даже в онлайн-режиме.

## 6. Модель данных

### 6.1. Room (Kotlin, кратко)

```kotlin
@Entity(tableName = "characters")
data class CharacterEntity(
    @PrimaryKey val id: String,            // uuid
    val name: String,                      // «Виктор Павлович»
    val tag1: String?, val tag2: String?, val tag3: String?,
    val kind: String,                      // "friend" | "teacher" | "other"
    val bgPreset: Int,                     // 0..5, см. 13.2
    val photoPath: String?,                // files/cards/<id>_cut.webp
    val cropJson: String?,                 // кроп/зум в исходнике
    val initials: String,                  // 1–2 буквы для фолбэка
    val createdAt: Long, val updatedAt: Long
)

@Entity(tableName = "players")
data class PlayerEntity(
    @PrimaryKey val id: String, val name: String,
    val isHost: Boolean = false, val lastSeenAt: Long
)

@Entity(tableName = "presets")                  // пресеты составов
data class PresetEntity(@PrimaryKey val id: String, val title: String,
                        val namesJson: String, val createdAt: Long)

@Entity(tableName = "sessions")
data class SessionEntity(@PrimaryKey val id: String, val startedAt: Long,
    val endedAt: Long?, val mode: String, val playerCount: Int,
    val showMs: Int, val seed: Long, val deckHash: String)

@Entity(tableName = "rounds")
data class RoundEntity(@PrimaryKey(autoGenerate = true) val id: Long = 0,
    val sessionId: String, val orderIndex: Int, val playerId: String,
    val playerName: String, val characterId: String, val characterName: String,
    val result: String?,                   // "guessed" | "missed" | "skipped" | null
    val shownMs: Int, val markedAt: Long?)
```

Индексы: `characters(kind)`, `characters(name)`, `rounds(sessionId)`. Все `Dao` — обычные suspend-функции, без Flow там, где не нужно.

### 6.2. Файл набора `.ktya`

ZIP (без пароля), внутри:

```
manifest.json
photos/<characterId>.webp        // 720×960, q80, вырезанное лицо с альфой
```

```json
{
  "format": "ktya/1",
  "exportedAt": 1731600000000,
  "title": "ИТ-21 + кафедра",
  "deckHash": "sha256:9f2c...",
  "characters": [
    {"id":"c1","name":"Виктор Павлович","tag1":"Доцент кафедры матана",
     "tag2":"строгий","tag3":null,"kind":"teacher","bgPreset":2,
     "initials":"ВП","photo":"photos/c1.webp"}
  ]
}
```

`deckHash` = sha256 от отсортированного по `id` списка `id|name|tag1|tag2|tag3|kind`. Импорт: если хэш совпадает — набор считается «тем же», если нет — конфликт `id` решается «оставить локальный / заменить / дублировать с суффиксом». Показывай это одним диалогом, не тремя.

## 7. Онбординг и библиотека персонажей

### 7.1. Онбординг (3 экрана, показывается один раз, скипается)

1. «Кто Я: Универ Edition. Телефон ко лбу, остальные подсказывают. Работает без интернета.» → «Дальше».
2. «Сначала нужны лица. Добавь друзей и преподов — по одному фото на человека.» → кнопка «Добавить персонажей» / «Позже».
3. «Запиши голос группы: «Три! Два! Один! Погнали!», «Красавчик!», «Эх, не угадал». Без записи будут синтезированные звуки.» → «Записать» / «Пропустить».

Кнопка «Пропустить» всегда доступна; игра без персонажей показывает не пустоту, а экран «Нужно минимум 2 персонажа» с одной кнопкой «Добавить».

### 7.2. Библиотека (S9)

- Верх: счётчик «12 персонажей · 5 друзей · 7 преподов», поиск по имени/тегу.
- Фильтр-чипы: Все / Друзья / Преподы.
- Сетка 2 колонки, карточки-миниатюры 3:4 с тем же фоном и подписью имени внизу.
- FAB «+ Добавить». Долгое нажатие на карточку → «Изменить», «Дублировать», «Удалить» (удаление — только с подтверждением; правило пользователя: никогда не удалять данные молча).
- Меню сверху: «Импортировать набор», «Поделиться набором», «Сортировка» (по имени / по дате / по типу).

### 7.3. Редактор персонажа (S10)

Порядок полей строго такой (сверху вниз, всё на одном экране со скроллом):

1. **Превью карточки** в реальном времени — ровно тот компонент, что в игре (масштаб 0.55). Меняется при каждом вводе.
2. **Фото:** большая кнопка-плитка «Добавить фото» → sheet: «Галерея» / «Камера» / «Убрать фото». После выбора — экран кропа: квадратный вьюпорт 3:4, пинч-зум 1–4×, перетаскивание, кнопка «Вырезать фон» (вкл. по умолчанию) и «Готово».
3. **Имя / ФИО** — 1..24 символа, обязательное, счётчик символов, автофокус при создании.
4. **Кто это** — сегмент-кнопки «Друг» / «Препод» / «Другое». Меняет цвет фона по умолчанию (синий / красный / графит) и порядок в раздаче (см. 10.3: колода чередует типы).
5. **Теги** — до 3 полей по 0..40 символов, плейсхолдеры: «Группа ИТ-21», «любитель поспать на парах», «строгий». Подсказки-чипы из уже использованных тегов.
6. **Фон карточки** — 6 кружков-пресетов (раздел 13.2), выбранный обведён.
7. Кнопки: «Сохранить» (primary, активна когда есть имя), «Удалить» (в режиме редактирования).

Валидация: пустое имя — кнопка неактивна; обрезка пробелов; запрет дубликата имени с точностью до регистра → предупреждение, но не блокировка (бывает два «Саши»).

### 7.4. Импорт фото — технические требования

- EXIF-поворот обязателен (`ExifInterface.ORIENTATION_*`), иначе половина фото ляжет набок.
- Даунскейл исходника до 1440 px по длинной стороне до сегментации (иначе ML Kit жрёт 300 МБ и падает на бюджетных телефонах).
- Сегментация: `SubjectSegmentation.getClient()`, вход `InputImage.fromFilePath`, выход — foreground bitmap с альфой. Таймаут 8 с (обёртка `withTimeout`), при ошибке/таймауте — фолбэк: прямоугольный кроп + скруглённые углы + тёмная виньетка, бейдж «фон не вырезан».
- Результат: `Bitmap` → WebP q80 → `filesDir/cards/<id>_cut.webp`, и thumb 360 px в `cacheDir` для списка. Исходник не хранится (или хранится только до подтверждения — настройка «Хранить оригиналы», по умолчанию выкл).
- Прогресс: «Вырезаю фон… 3 из 12» для батч-импорта, отменяемая `Job`.
- Мультивыбор фото в галерее: `PickMultipleVisualMedia(maxItems = 30)`, для каждого файла создаётся черновик персонажа с именем файла как подсказкой.
- Камера: `TakePicture` → сразу кроп + сегментация.
- Всё в `Dispatchers.IO`, никогда в main.

### 7.5. Заглушки вместо реальных фото и голосов (обязательно с первого запуска)

**Ситуация:** настоящие фотографии друзей и преподавателей, а также записанные голоса Рустам
пришлёт **после** того, как приложение будет готово. До этого момента игра должна быть
полностью играбельной: ни одного пустого экрана, ни одного «фото не добавлено», ни одной
тишины там, где по механике должен быть звук. Пустые серые прямоугольники вместо лиц — брак.

**Три правила, которые нельзя нарушать:**

1. **Банк уже внутри APK.** `assets/characters.json` + `assets/characters/*.png` +
   `assets/sounds/*.wav`. При первом запуске, если Room пуст, база наполняется из assets
   (`seedFromAssets()`), и кнопка «Играть» работает сразу. Онбординг не должен упираться в
   «добавь фото»: он предлагает «Играть с заглушками» / «Добавить свои лица».
2. **Имена файлов — контракт.** Пользователь кладёт реальное фото с тем же именем
   (`friend_ivan.png`) и пересобирает APK — код не меняется. Никаких «вставь сюда base64»,
   никаких настроек путей в UI.
3. **Отсутствующий/битый файл — фолбэк, а не краш.** Нет PNG → инициалы на градиенте
   (раздел 12.3). Нет голоса → общий звук. Нет обоих → сгенерированный тон.

**Состав банка-заглушки — 12 записей: 8 друзей, 4 препода.** Имена и теги заданы заранее
(их легко переписать), `bgPreset` чередуется:

**Как рисовать фото-заглушки.** Скрипт `tools/gen_placeholders.py` (Python + Pillow,

- фон полностью прозрачный (чтобы проверить `ContentScale.Fit`, как на реальном вырезанном лице);
- круг диаметром 900 px со скруглением-градиентом цвета роли (друг — синий, препод — красный);
- инициалы по центру, шрифт 320 px, белый, bold (DejaVuSans-Bold из системных, с фолбэком
  на любой ttf из `C:\Windows\Fonts`);
- простенькая нейтральная «рожица»: две точки-глаза + дуга-улыбка поверх инициалов, прозрачность 25 %;
- внизу капсом `PLACEHOLDER`, 56 px, 45 % прозрачности.

Результат коммитится в репозиторий (`assets/characters/*.png`), скрипт тоже — чтобы картинки
можно было перегенерировать при добавлении человека. Никаких скачиваний из интернета.

**Звуки-заглушки.** Скрипт `tools/gen_tones.py` (Python, `wave` + `struct`), WAV 44.1 кГц,

|---|---|---|
| `assets/sounds/go.wav` | голос старосты «Три! Два! Один! Погнали!» | 880 Гц 120 мс ×2, 1100 Гц 120 мс, восходящий тон 300→1200 Гц 220 мс |

| `assets/sounds/win.wav` | «Красавчик!» | мажорный аккорд 523+659+784 Гц, 400 мс |
| `assets/sounds/skip.wav` | «Эх, не угадал» | минорный 440+523+659 Гц, 400 мс |

`assets/sounds/<characterId>_win.m4a` (AAC, ≤ 3 с).

**Приоритет звука (проверяется тестом, тишины нет ни в одном случае):**

```
личный звук персонажа из assets/sounds/<id>_win.m4a
  → записанный голосовой пак из настроек (13.1)
    → сгенерированный assets/sounds/win.wav
```

**Экран «Заглушки» (S14, вход из настроек):**

- Две строки-счётчика: «Фото: 5 своих, 7 заглушек», «Голоса: 1 из 4 записано».
- Список 12 персонажей: миниатюра, имя, бейдж `своё фото` / `заглушка` / `нет файла`.
- Кнопка «Обновить банк персонажей» — перечитывает `characters.json` и assets без перезапуска
  (для отладки: подложил файл через файловый менеджер → нажал → увидел).
- Инструкция в 4 строки (дублирует README).

**Инструкция замены (README + этот экран, ровно 4 шага):**

1. Положи фото `friend_ivan.png` в `android/app/src/main/assets/characters/` — PNG с
   прозрачным фоном, ≥ 800×800, лицо по центру, лучше смешная эмоция.
2. Положи голос `friend_ivan_win.m4a` в `android/app/src/main/assets/sounds/` (AAC, ≤ 3 с) —
   для «Красавчик!» этим человеком; без файла играет общий `win.wav`.
3. Новый человек — добавь объект в `characters.json` (id, name, kind, tags, photo, initials).
4. `./gradlew :app:assembleDebug` (или дождись CI) — APK уже с настоящими лицами.

**Кэш:** assets-фото **не** копируются в `filesDir/cards`, поэтому замена файла в APK всегда
видна (кэш cutout относится только к фото, импортированным с телефона через 7.4). Импорт из
галереи остаётся: assets = стартовое наполнение, Room = то, что пользователь добавил или
заменил сам; при совпадении `id` локальная версия выигрывает и помечается «изменено вручную».

## 8. Состав игры (S2)

- **Количество игроков:** 2–10, степпер «− 6 +» крупный, палец должен попадать без прицеливания.
- **Имена игроков:** вертикальный список строк `Игрок 1 … Игрок 6`, каждая — редактируемое поле, автофокус на первой пустой. Кнопки «Заполнить пресетом», «Сохранить как пресет», «Очистить».
- **Колода:** чипы наборов, если наборов несколько; показывает «12 карточек, из них 5 друзей / 7 преподов». Если карточек < игроков — жёлтая плашка «Карточек меньше, чем игроков: кто-то получит повтор. Добавить персонажей?».
- **Раунд:** «Показ 10 с» (варианты 5/10/15/20/30, по умолчанию 10) — чипы.
- **Опции:** «Отмечать результат после показа» (**по умолчанию выкл** — по основному сценарию после показа телефон сразу передаётся дальше; если включить, появляется экран «Угадал?» и в итогах считается счёт), «Чередовать друзей и преподов» (вкл), «Вибрация» (вкл), «Звук» (вкл).
- Кнопка «Поехали» → S3. Валидация: минимум 2 непустых имени, минимум 2 персонажа.

Пресеты: сохраняется просто список имён + порядок. При запуске — если есть пресет, показывается одной строкой «Вчерашний состав: Рустам, Аня, Дима, +3 · Применить».

## 9. Локальный режим — точная механика

### 9.1. Машина состояний

```
S2 Setup ──▶ S3a Pass(player i) ──▶ S3b Countdown ──▶ S4 Show(10s) ──▶ S5 Mark
                   ▲                                                     │
                   └────────────── i+1 < N ◀────────────────────────────┘
                                       │ i+1 == N
                                       ▼
                                  S6 Review ──▶ S8 Summary
```

Каждый шаг — отдельный экран (не диалог, не bottom sheet): человек держит телефон в воздухе, промахнуться по кнопке нельзя.

**S5 «Отметка» показывается только если в составе включена опция «Отмечать результат после показа»** (по умолчанию выключена). При выключенной опции поток: S4 → S3a следующего игрока; после последнего — S6, а S8 «Итоги» становится экраном раскрытия «кто кем был» без счёта и победителя. Оба варианта обязаны быть проверены вручную.

### 9.2. Тайминги (жёсткие, `docs/TIMINGS.md`)

| Фаза | Длительность | Видимое | Звук | Вибрация |
|---|---|---|---|---|
| S3a «Возьми телефон» | до тапа | «Игрок 3, Аня. Возьми телефон, поверни экраном к остальным и нажми "Готово"» + большая кнопка | нет | короткий 30 мс при входе |
| S3b Отсчёт | 3 × 800 мс + 400 мс на «Погнали!» | цифры 3 → 2 → 1 на весь экран, затем «Погнали!» | писк 880 Гц каждый шаг, на «Погнали» — 1320 Гц длиннее; если записан голосовой пак — играет он | 3 коротких, затем одна длинная |
| S4 Показ | `showMs` = 10 000 | карточка персонажа на весь экран, в углу тонкий прогресс-обод и цифры «10…1» | тики: 1000, 800, 600 Гц на последних 3 с (ускоряющиеся, `Tones.tick`), на 0 — «дзынь» | парные короткие импульсы на последних 3 с |
| S5 Отметка | до тапа | «Ты угадал?» + имя персонажа мелким, две кнопки: «Угадал» / «Не угадал», третья «Пропустить раунд» | на «Угадал» — голосовая реплика «Красавчик!», на «Не угадал» — «Эх, не угадал» | разная: успех = один длинный, провал = два коротких |
| S6 Разбор | до действия | сетка N карточек + статусы | без звука (кроме тихого тапа) | — |
| S8 Итоги | до действия | победитель, статистика | короткий фанфарный аккорд (3 ноты) | — |

Правила:
- Отсчёт и показ идут на `SystemClock.elapsedRealtime()` с шагом кадра 100 мс, а не на цепочке `delay(1000)` (иначе дрейф на 200–400 мс и тики «плывут»).
- Никаких `Dialog`, `Snackbar` и системных уведомлений в S3b/S4: полноэкранный режим (`WindowCompat.setDecorFitsSystemWindows(false)`, скрытые бары), `FLAG_KEEP_SCREEN_ON`, яркость окна = `BRIGHTNESS_OVERRIDE_FULL`.
- Экран всегда портретный на S3–S5 (`screenOrientation="portrait"` для Activity; поворот не должен ломать таймер).
- Кнопка «Назад» на S3b/S4 перехватывается: первый тап — «Отменить показ?» с кнопками «Отмена» / «Прервать раунд».

### 9.3. Раздача персонажей

```kotlin
// Deck.kt — единственная реализация, используется и локально, и в онлайне
fun deal(seed: Long, deck: List<String>, players: List<String>,
         alternateKinds: Boolean, kindOf: (String) -> String): Map<String, String> {
    val rnd = java.util.Random(seed)                 // документированный PRNG
    fun shuffle(list: List<String>): List<String> {  // Fisher–Yates
        val a = list.toMutableList()
        for (i in a.lastIndex downTo 1) { val j = rnd.nextInt(i + 1); a[i] = a[j].also { a[j] = a[i] } }
        return a
    }
    val friends = shuffle(deck.filter { kindOf(it) == "friend" })
    val teachers = shuffle(deck.filter { kindOf(it) == "teacher" })
    // чередуем типы, если alternateKinds и обоих типов хватает,
    // затем добираем из остатка; повторы только если deck.size < players.size,
    // и тогда два одинаковых персонажа никогда не идут подряд
    ...
}
```

Требования к раздаче (проверяются юнит-тестами):
1. Внутри одного раунда персонажи не повторяются, если `deck.size >= players.size`.
2. При `deck.size < players.size` возможны повторы, но не у соседних игроков, и у каждого игрока ровно один персонаж.
3. При включённом чередовании типов последовательность максимально «друг-препод-друг-препод».
4. Функция детерминирована: `deal(42L, …)` даёт одинаковый результат на любом устройстве и в любой момент.

### 9.4. S6 «Разбор» — обязательная механика

- Заголовок «Разбор. Кто кем был», подзаголовок «Нажми на карточку, чтобы показать ещё раз».
- Сетка 2 колонки: мини-карточка 3:4 (тот же `CharacterCard` в масштабе 0.5), над ней имя игрока, под ней статус «Угадал ✓ / Не угадал ✗ / Пропустил —».
- Тап по карточке → S7: полноэкранный повторный показ того же персонажа на `showMs` секунд с теми же тиками и прогресс-ободом, но **без** голосового отсчёта; по истечении — возврат в S6. В S7 есть крестик «Закрыть» (для того, кто держит телефон, а не для зрителей).
- Долгое нажатие → «Изменить результат» (маленькое меню: Угадал / Не угадал / Пропустил).
- Внизу липкая панель: «Ещё раунд» и «Закончить игру» (primary). «Закончить» доступно всегда, в том числе посреди игры — тогда в отчёте незавершённые раунды помечены «не прошли».

### 9.5. S8 «Итоги»

- Крупно: «Угадали 4 из 6» + имя лучшего (при равенстве — «ничья: Аня и Дима»).
- Список по убыванию: место, имя игрока, его персонаж (мини-аватар), статус.
- Статистика мелким: «Друзей угадали 3/4», «Преподов 1/2», «Средний показ 10 с».
- Кнопки: «Ещё раунд» (новый seed, тот же состав, обнуление результатов), «Поделиться» (скриншот итогов через `FileProvider` + `ACTION_SEND`), «В меню».
- Строка «Результаты сохраняются только на этом телефоне» — честность вместо аналитики.

## 10. Онлайн-режим

### 10.1. Принципы

- Хост создаёт комнату → сервер отдаёт код из 6 символов: алфавит `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (без `I`, `O`, `0`, `1` — их путают на слух и на глаз), коллизии исключены генерацией «пока не свободен», TTL комнаты 90 минут.
- Игроков 2–10. Имя 1..16 символов, дубликаты запрещены на уровне сервера (`Аня`, `аня` — конфликт, ответ `NAME_TAKEN`).
- **Фото не уходят в сеть.** Сервер хранит только: код, id/имена игроков, hostId, фазу, seed, число раундов, результат каждого (guessed/missed/skipped). Клиенты раздают карточки сами по seed.
- Хост жмёт «Начать» → сервер фиксирует `startAt = now + 1500 мс` (запас на доставку), рассылает `round_start` с `startAt`, `showMs`, `seed`, `order[]`. Все клиенты считают отсчёт по `server time` с коррекцией смещения.
- Отметка результата — свободная, каждый сам жмёт «Угадал / Не угадал» на своём телефоне (в онлайне нет ведущего). Результаты видны только в итогах.
- В конце хост жмёт «Раскрыть всех» → сервер рассылает `reveal`, каждый клиент рендерит список «игрок → персонаж» (персонаж берётся из локальной колоды по id из `order`).
- Хост может: «Ещё раунд», «Исключить игрока» (только в лобби), «Закрыть комнату». Если хост ушёл — комната живёт 60 с, затем закрывается; в лобби хост передаётся первому по времени входа.

### 10.2. Протокол WebSocket (JSON, `wss://…/ws`)

**Клиент → сервер**

| type | поля | когда |
|---|---|---|
| `hello` | `proto:1, clientId, appVersion, lang` | сразу после connect |
| `create` | `name, deckSize, deckHash` | создать комнату |
| `join` | `code, name` | войти |
| `rejoin` | `code, playerId, token` | восстановление после обрыва |
| `ready` | `ready:boolean` | лобби |
| `start` | `showMs, alternateKinds` | хост |
| `result` | `round:int, value:"guessed"\|"missed"\|"skipped"` | после показа |
| `reveal` | `round:int` | хост |
| `next_round` | — | хост |
| `leave` | — | выход |
| `ping` | `t` | каждые 20 с |

**Сервер → клиент**

| type | поля |
|---|---|
| `hello_ok` | `serverTime, proto:1` |
| `room` | `code, hostId, phase:"lobby"\|"countdown"\|"show"\|"mark"\|"reveal"\|"closed", players[{id,name,ready,online}], round, deckSize, deckHash` |
| `countdown` | `startAt, showMs, order[]` (order = `[characterId]` по индексу игрока в `players`) |
| `results` | `map{playerId: value}, allDone:boolean` |
| `reveal` | `order[], names{}, stats{}` |
| `error` | `code:"ROOM_NOT_FOUND"\|"ROOM_FULL"\|"NAME_TAKEN"\|"ALREADY_STARTED"\|"NOT_HOST"\|"BAD_VERSION", message` |
| `pong` | `t` |

Правила: сообщение ≤ 4 КБ, `ws` с `maxPayload: 8192`; heartbeat: сервер закрывает соединение после 60 с без `ping`; `phase` меняет только сервер, клиент никогда не «додумывает» состояние, а рендерит `room`. Клиент обязан пережить: `room` без своего `playerId`, повторный `room` с той же фазой (идемпотентный рендер), `error` в любой момент.

### 10.3. Синхронизация времени

```
получен hello_ok(serverTime) → skew = serverTime - System.currentTimeMillis()
offset пересчитывается каждые 60 с (усреднение 3 измерений, отброс выбросов > 400 мс)
отображение: remaining = startAt - (System.currentTimeMillis() + skew)
если |skew| > 2000 мс — баннер «Время на телефоне сильно отличается от сервера»
```

На клиенте при `countdown` — экран отсчёта; при `remaining <= 0` — сразу S4, без ожидания дополнительного сообщения.

### 10.4. Экраны онлайна

- **S11a Вход:** две большие кнопки «Создать игру» / «Войти по коду», поле сервера (редактируемое, по умолчанию из `BuildConfig.SERVER_URL`, «Сбросить»), статус связи точкой (зелёная/жёлтая/красная + текст «сервер просыпается…»).
- **S11b Код:** 6 клеток, крупные цифры-буквы, кнопка «Копировать» и «Поделиться» (`ACTION_SEND` текстом «Заходи в Кто Я: код K7M2QX»).
- **S11c Лобби:** код сверху мелким, список игроков с точками online, хост видит «Начать» (активна при ≥2 игроках и всех `ready`), остальные — «Ждём хоста…» + «Готов».

## 12. Дизайн-система

### 12.1. Тон и стиль

Дружеский, короткий, с лёгкой иронией, обращение на «ты», без канцелярита и без эмодзи в каждом предложении (максимум один на экран, кроме итогов). Никаких «Ой! Что-то пошло не так» — только конкретика: «Сервер не отвечает. Проверь Wi-Fi или начни игру на одном телефоне».

### 12.2. Палитра

| Токен | Тёмная тема | Светлая | Где |
|---|---|---|---|
| `bg` | `#101014` | `#F6F6F8` | фон приложения |
| `surface` | `#1A1A21` | `#FFFFFF` | карточки интерфейса |
| `accent` | `#FFB020` | `#F59300` | primary-кнопки, прогресс |
| `friend` | `#2563EB → #1E40AF` | то же | фон карточки друга |
| `teacher` | `#DC2626 → #991B1B` | то же | фон карточки препода |
| `other` | `#334155 → #1E293B` | то же | «другое» |
| `text` | `#F7F7FA` | `#111114` | основной текст |
| `muted` | `#9AA0AA` | `#6B7280` | подписи, теги |

6 пресетов фона карточки (`bgPreset 0..5`): синий, красный, изумрудный `#059669`, фиолетовый `#7C3AED`, янтарный `#B45309`, графит. Все — градиент 135°, контраст белого текста ≥ 4.5:1. Проверяй в тесте: для каждого пресета `contrast(white, topColor) >= 4.5` (см. 20.1).

### 12.3. Карточка персонажа — эталон (главный элемент)

Пропорции внутри карточки (весь экран минус 24 dp по краям, скругление 28 dp, `clipToOutline`):

```
┌──────────────────────────────────────┐   градиент фона по типу персонажа
│  [тип]                    №3 из 6    │   14 sp, 60% прозрачности, отступ 20
│                                      │
│           ╭──────────╮               │   фото: 62% высоты,
│           │  вырезан- │              │   ширина ≤ 78%, центр по X,
│           │  ное лицо │              │   тень 0/12/32 rgba(0,0,0,.35),
│           ╰──────────╯               │   белая обводка 4 dp (видна на любом фоне)
│                                      │
│         ВИКТОР ПАВЛОВИЧ              │   имя: авторазмер 40→64 sp,
│                                      │   maxLines 2, bold, letterSpacing -0.5
│   Доцент кафедры матана · строгий    │   теги: 15 sp, 85% прозрачности,
└──────────────────────────────────────┘   maxLines 2, ellipsis
```

Правила:
- Имя — самое крупное, читается с 2.5 метра: минимум 40 sp при любом имени (для длинных ФИО включи `AutoSize` от 64 до 34 sp, `maxLines = 2`).
- Если имя длиннее 24 символов — уменьшать размер, а не обрезать.
- Фото при отсутствии: инициалы 120 sp белым на затемнённом фоне + подпись «фото нет».
- Метка типа сверху: «ДРУГ» / «ПРЕПОД» / «ДРУГОЕ» капсом, 12 sp, letterSpacing 1.5.
- Никаких рамок, теней интерфейса и логотипов поверх фото.
- В масштабе 0.5 (разбор) и 0.55 (превью) все размеры шрифтов множатся на коэффициент — один компонент, параметр `scale: Float`.

### 12.4. Типографика

Шрифт — Roboto Flex или Rubik (OFL, положить в `res/font/`, `fontVariationSettings` не нужен). Размеры: H1 34/40 bold, H2 26/32 semibold, body 16/24, caption 13/18, метка 12/16 + tracking 1.5. На экранах S3–S5 всё минимум на ступень крупнее обычного (это экран, который смотрят издалека).

### 12.5. Движение

- Появление карточки: `fadeIn + scaleIn(0.94→1)` за 220 мс, `FastOutSlowIn`.
- Цифры отсчёта: смена через `AnimatedContent` с scale 1.4→1 и fade 120 мс.
- Переходы между экранами: `slideInHorizontally(1/4)` 260 мс / `slideOutHorizontally(-1/4)`; переход S6→S7 — `fadeIn` 180 мс (чтобы не «мигало» при повторном показе).
- Прогресс-обод в S4: значение обновляется каждые 100 мс (`animateFloatAsState` с `LinearEasing`, не spring — иначе отстаёт).
- Никаких `animateContentSize` на карточке персонажа.
- Уважай `Settings.Global.ANIMATOR_DURATION_SCALE == 0` (отключённые анимации в системе): все длительности → 0, но таймеры игры идут.

### 12.6. Мелкое, но обязательное

- `FLAG_KEEP_SCREEN_ON` на S3b/S4/S5/S7.
- Яркость окна: `BRIGHTNESS_OVERRIDE_FULL` на S4/S7, восстановление при выходе (в `DisposableEffect`).
- Вибрация: `VibratorManager` (API 31+) с фолбэком на `Vibrator`; паттерны: старт `[0,60,80,60,80,120]`, успех `[0,120]`, провал `[0,40,60,40]`, тик `[0,25]`.
- Блокировка сна не отключается — но если пользователь заблокировал экран в S4, таймер продолжает идти, при возврате показывается актуальная фаза (не перезапуск!).
- Системную «шторку» не перехватываем.

## 13. Звук и озвучка

### 13.1. Голосовой пак (S13) — 4 слота

| Слот | Текст-подсказка | Когда играет |
|---|---|---|
| `start` | «Три! Два! Один! Погнали!» | вместо писков в S3b |
| `guessed` | «Красавчик!» | на отметке «Угадал» |
| `missed` | «Эх, не угадал» | на отметке «Не угадал» |
| `final` | «Всё, хватит, играем ещё» | на S8 |

- Запись: `MediaRecorder`, AAC 44.1 кГц mono 96 кбит/с, максимум 4 с, `AudioRecord` уровень виден как индикатор, «Прослушать», «Перезаписать», «Удалить».
- Файлы: `filesDir/voice/<slot>.m4a`. Пак привязан к колоде/набору? Нет — глобально, один на устройство (проще).
- Разрешение `RECORD_AUDIO` запрашивается только при первом нажатии «Записать», с объяснением на экране («Голос останется только на этом телефоне»).
- Если слот пуст → файл-заглушка `assets/sounds/<slot>.wav` (7.5), затем Android TTS с русской локалью (проверить `TextToSpeech.isLanguageAvailable(RUSSIAN)`), и только в последнюю очередь — тон из 13.2. Пустой слот не должен означать тишину.

### 13.2. Синтезированные звуки (без внешних файлов)

- Отсчёт: `ToneGenerator`/заранее сгенерированный WAV 880 Гц, 120 мс, attack/release 10 мс (иначе щёлкает).
- «Погнали»: 1320 Гц, 260 мс.
- Тики: 1000/800/600 Гц по 60 мс, громкость растёт (0.5 → 0.8 → 1.0).
- «Дзынь» конца показа: два тона 1568 + 2093 Гц через 60 мс.
- Фанфары итогов: 523 / 659 / 784 Гц по 140 мс.
- Все сэмплы генерируются скриптом `tools/gen_tones.py` (Python, `wave` + `struct`) → `assets/sounds/*.wav`, 44.1 кГц 16 бит mono. В репозитории лежат и скрипт, и результат. `res/raw/` для этих же звуков не использовать: два места с одинаковыми именами — гарантированная путаница при замене файлов на настоящие голоса.

### 13.3. Звуковой движок

`SoundPool(maxStreams = 4)`, заранее загруженные сэмплы, `AudioAttributes.USAGE_GAME`, `playbackRate 1.0`. Реплики — `MediaPlayer` с `setOnCompletionListener` и обязательным `release()`. Всё звучание глушится тумблером «Звук» (сохраняется в DataStore) и уважает `AudioManager.getStreamVolume(STREAM_MUSIC) == 0` → ничего не играем и не вибрируем (не глушим пользователя в наушниках, но и не пищим в тишине).

### 13.4. Заменяемые голоса из assets (связка с 7.5)

Каждый короткий звук — файл в `assets/sounds/` с фиксированным именем, и это единственный
контракт с пользователем. Порядок выбора при воспроизведении:

1. `assets/sounds/<characterId>_win.m4a` / `<characterId>_skip.m4a` — личная реплика персонажа
   (если человек прислал свой голос именно для этой карточки);
2. записанный слот голосового пака из 13.1 (`filesDir/voice/<slot>.m4a`);
3. общий `assets/sounds/go.wav | win.wav | skip.wav | tick.wav | time_up.wav | click.wav`.

Правила, которые легко забыть:

- Отсчёт 3-2-1 **не** режется под длину файла: если `go.wav` длиннее 2 с (человек записал
  «Три! Два! Один! Погнали!»), игра не ждёт его окончания — визуальный отсчёт идёт по своим
  таймингам, звук просто доигрывает. Обратное тоже верно: короткий файл не продлевает фазу.
- Формат: `SoundPool` не умеет длинные файлы — реплики длиннее 3 с играть через `MediaPlayer`,
  выбор по размеру файла, а не по имени.
- Битый или отсутствующий файл → следующий пункт цепочки, без `IOException` наружу.
- Проверка в тесте: для персонажа с пустым `sounds` играется общий `win.wav`, для персонажа
  с указанным файлом — именно он (подменяем `SoundPool` фейком и смотрим вызов).

`assets/sounds/` должен попасть в APK **без** сжатия (`androidResources { noCompress += listOf("wav", "m4a") }`), иначе на части устройств файл читается медленнее и первый тик опаздывает.

## 16. Языковая и техническая гигиена

1. `minSdk 26` — нет нужды в `Desugaring`; используй только API, доступные с 26, или `if (Build.VERSION.SDK_INT >= …)`.
2. `Locale` в рантайме: язык хранится в `SharedPreferences` (синхронно), применяется в `attachBaseContext(newBase)` через `createConfigurationContext`; смена языка → `activity.recreate()`. Одинаковый набор ключей в `values/` и `values-en/` — проверять скриптом (`tools/check_strings.py`, регулярка по `name="…"`, наборы должны совпадать один-в-один).
3. Все размеры — в `dp/sp`, никаких `px`. Проверить на 320 dp по ширине (маленький телефон) и на 411 dp.
4. `AutoSize` текста: не более двух строк, `TextAutoSize.StepBased` или ручной расчёт по длине строки.
5. `@Preview` для каждой карточки/экрана с фейковыми данными — но настоящие тесты идут через Robolectric.
6. Никаких `LocalContext.current` в `remember` без причины; ViewModel переживает поворот (`viewModel()` из `lifecycle-viewmodel-compose`).
7. Все файлы — UTF-8, `strings.xml` без «умных» кавычек, которые ломают XML.

## 17. Крайние случаи (каждый покрыть кодом + тестом)

1. Игроков 2 → в разборе 2 карточки, сетка не растягивается на весь экран уродливо (центрировать, maxWidth 520 dp).
2. Игроков 10 → сетка скроллится, липкая панель снизу не перекрывает последний ряд.
3. В колоде 1 персонаж → блокирующая плашка «Нужно минимум два персонажа», кнопка «Поехали» неактивна с подписью причины.
4. Имя длиной 24 символа и 3 длинных тега → ничего не выходит за карточку, имя уменьшается.
5. Фото отсутствует/битое → инициалы, бейдж «нет фото».
6. Сегментация упала → фолбэк-кроп, играбельно.
7. Пользователь свернул приложение в S4 → таймер идёт дальше, при возврате актуальная фаза или S5, если время вышло.
8. Входящий звонок в S4 → `onPause` не сбрасывает раунд; звук восстанавливается.
9. Отключён звук в системе → нет тонов, но вибрация работает (и наоборот, если выбрана только вибрация).
10. Поворот экрана в S6/S8 → состояние сохраняется (`rememberSaveable` + ViewModel).
11. Онлайн: комната не существует → понятная ошибка, поле кода остаётся для правки, кнопка «Назад» работает.
12. Онлайн: имя занято → предложить «%1$s 2».
13. Онлайн: хост закрыл приложение → через 60 с комната закрыта, у остальных «Игра закончилась» + «Создать новую».
14. Онлайн: у игрока разные наборы (хэш не совпал) → баннер «У вас разные наборы карточек: персонажи могут отличаться», игра продолжается.
15. Онлайн: повторный `rejoin` после убийства приложения → `playerId` и `token` в DataStore, возврат в ту же фазу.
16. Часы устройства сбиты на 5 минут → коррекция по `hello_ok`, а при `|skew| > 2000` баннер.
17. Двойной тап «Начать» → сервер идемпотентен (`ALREADY_STARTED` игнорируется клиентом), отсчёт не сбрасывается.
18. Импорт набора с дубликатами id → диалог «Заменить / Оставить оба».
19. «Стереть данные» → файлы `filesDir/cards`, `filesDir/voice`, Room и DataStore вычищены; проверить, что размер `filesDir` уменьшился (тест).
20. Низкий заряд/энергосбережение → нет фоновых задач, нет `AlarmManager`, ничего не «съедает» батарею между раундами.

## 20. Тесты и критерии приёмки

### 20.1. Обязательные автотесты

**Kotlin (unit, JVM):**
1. `DeckTest`: без повторов при `deck.size >= players`; повторы не подряд при нехватке; детерминизм (`seed(42)` дважды → одинаковый результат); чередование типов ≥ 80% переходов при достаточном количестве обоих типов.
2. `CodeGenTest`: 6 символов, алфавит без `IO01`, 10 000 генераций — все уникальны в пределах активных комнат (на стороне сервера) и валидны по regex `^[A-HJ-NP-Z2-9]{6}$`.
3. `TimingTest`: `LocalGameEngine` на виртуальном времени выдаёт фазы ровно в 0 / 2400 / 3400 / 13400 мс (отсчёт 3×800 + 400 «Погнали» + 10 000 показа); при `showMs = 5000` — 7400 мс.
4. `StringsTest`: набор ключей ru == en; ни одна строка в коде не хардкожена (грубая проверка регуляркой по `"` с русскими буквами в `screens/*.kt` — допускается только в тестах/превью).
5. `ContrastTest`: для каждого из 6 пресетов фона контраст белого текста ≥ 4.5.
6. `SetFileTest`: экспорт → импорт → `deckHash` совпадает, все персонажи на месте; битый zip → понятная ошибка, не краш.
7. `RepoTest` (Room in-memory): CRUD персонажей, каскадное удаление файлов, «стереть данные» → 0 строк и 0 файлов.
7a. `BankAssetsTest`: `characters.json` из assets парсится в 12 записей (8 friend / 4 teacher), у каждого есть PNG и инициалы; `seedFromAssets()` на пустой базе создаёт 12 строк, повторный вызов не дублирует; удаление всех персонажей и повторный запуск снова наполняет банк (пользователь не может «сломать» игру насовсем).
7b. `PlaceholderFallbackTest`: отсутствующий PNG не роняет рендер карточки (инициалы), отсутствующий звук не роняет воспроизведение (играется общий), битый PNG (несколько байт) — то же.
7c. `SoundPriorityTest`: личный звук персонажа → голосовой пак → общий; проверяется на фейковом `SoundPool`/`MediaPlayer`.

**Robolectric + Compose (render):**
8. S2 рендерится с 2/10 игроками, кнопка «Поехали» активна/неактивна по валидации.
9. S4 с длинным именем и 3 тегами: текст не выходит за карточку (`assertExists` + проверка `maxLines`).
10. S6 с 6 карточками: присутствуют 6 имён игроков и 6 статусов.
11. S8: «Угадали 4 из 6» присутствует.
12. Локаль: `qualifiers = "ru-rRU-w411dp-h891dp-xxhdpi"` для русских тестов и отдельный `en-rUS` для английских.

**Сервер (`node --test`):**
13. create → 6-символьный код; join вторым игроком; список в `room`.
14. join с занятым именем → `NAME_TAKEN`; 11-й игрок → `ROOM_FULL`.
15. `start` не хостом → `NOT_HOST`; повторный `start` → `ALREADY_STARTED` без изменения `startAt` у остальных.
16. `rejoin` с валидным токеном возвращает ту же фазу и того же игрока; с невалидным → `ROOM_NOT_FOUND`.
17. TTL: комната старше 90 минут → `ROOM_NOT_FOUND`, память освобождена (проверить размер `Map`).
18. Обрыв: игрок не пинговал 60 с → `online:false` в `room`, но место сохраняется 5 минут.

## 22. Сборка и раздача APK (Windows, без Android Studio)

Портативный тулчейн (JDK 17 + cmdline-tools + Gradle 8.10.2), лицензии через `yes |`, `android/local.properties` с `sdk.dir`, обёртка `gradle wrapper --gradle-version 8.10.2` **после** создания `settings.gradle.kts`.

```bash
export JAVA_HOME="C:/Users/<user>/AppData/Local/atc/jdk-17.0.21+9"
export ANDROID_HOME="C:/Users/<user>/AppData/Local/atc/android-sdk"
cd android && ./gradlew :app:testDebugUnitTest :app:assembleDebug --console=plain
"$ANDROID_HOME/build-tools/35.0.0/aapt2.exe" dump badging app/build/outputs/apk/debug/app-debug.apk | head
"$ANDROID_HOME/build-tools/35.0.0/apksigner.bat" verify --print-certs app/build/outputs/apk/debug/app-debug.apk
```

Грабли, которые уже проверены на практике (не наступать):
- `.gitignore` с правилом `data/` вырезает Kotlin-пакет `.../data/` → CI падает на `Unresolved reference 'data'`. Лечится `!android/app/src/main/java/com/kstoya/univer/data/**`, проверяется `comm -23` между `find` и `git ls-files`.
- Debug-APK из CI подписывается новым ключом каждый билд → «Приложение не установлено» поверх старой версии. Кладите `debug.keystore` в репозиторий и укажите `signingConfig` для debug; проверяйте одинаковый SHA-256 у локальной и CI-сборки.
- `background=true` для Gradle в этой среде не возвращает управление — запускайте в foreground с `timeout 590` и логом в файл, потом грепайте `^e: `.
- `git -C /c/...` не работает (MSYS не транслирует пути нативным бинарям) — делайте `cd`, потом `git`.
- Free-хостинг сервера засыпает через ~15 минут: пинг workflow каждые 10 минут + «сервер просыпается…» в UI + 3 попытки на первый запрос.

Раздача: ссылка + файл `MEDIA:C:\путь\app-debug.apk` в чат. Gmail режет `.apk` — не пытаться.

## Приложение А. Как снимать/собирать лица (инструкция в приложении, экран «Галерея → ?»)

- Фронтальная камера, вспышка выключена, фон однотонный (стена) — тогда вырезание идёт идеально.
- Лучше серия кадров: «сделай 5 рож» → выбираешь самый смешной. Эмоция важнее качества.
- Свет сбоку/сверху, не сзади. Не контровой свет через окно — лицо станет тёмным.
- Не сжимай фото в мессенджере перед добавлением: вырезание на мыле даёт рваный контур.
- Имя — так, как его зовут в компании, теги — то, за что его дразнят; но без травли и без того, что человеку будет неприятно (правило: если бы он это увидел — было бы смешно, а не обидно).

## Приложение Б. Короткий промпт (если модель не тянет длинное ТЗ)

> Сделай Android-игру «Кто Я: Универ» на Kotlin + Jetpack Compose (minSdk 26, compileSdk 35, AGP 8.7.3, Kotlin 2.0.21, Room, Coil, ML Kit subject-segmentation). Библиотека персонажей: фото из галереи/камеры, вырезание по контуру на устройстве, имя, до 3 тегов, тип «друг/препод/другое», 6 пресетов фона, экспорт/импорт набора `.ktya` (zip: manifest.json + webp). Плюс банк-заглушка в `assets/`: 12 персонажей (8 друзей / 4 препода) с генерированными PNG-«лицами» (инициалы на градиенте, прозрачный фон) и WAV-звуками (бипы и аккорды вместо голосов), которые наполняют пустую базу при первом запуске — игра должна проходиться целиком до того, как пользователь пришлёт настоящие фото и голоса; реальные файлы подменяются по тем же именам (`characters/friend_ivan.png`, `sounds/go.wav`, `sounds/<id>_win.m4a`) без правок кода, отсутствующий файл → инициалы/общий звук, никогда не краш. Локальный режим на 2–10 игроков: экран передачи → отсчёт 3-2-1 с писком и вибрацией → показ карточки 10 с на весь экран (keep-screen-on, максимальная яркость, тики на последних 3 с) → «Угадал?» → следующий; после всех — «Разбор» с сеткой карточек, повторным показом любой карточки на 10 с и «Закончить игру» → итоги. Онлайн: Node+ws сервер в памяти, комната по 6-символьному коду, лобби, синхронный старт по server time, тап по карточке скрывает её, раскрытие в конце; фото в сеть не уходят — раздача по seed локально (`Deck.deal`). Карточка: градиент (друг — синий, препод — красный), вырезанное лицо 62% высоты с белой обводкой, имя 40–64 sp, теги 15 sp. Звук: сгенерированные тоны + записанные голосом 4 реплики. Русский UI, строки только в strings.xml, тёмная тема. Тесты: Deck, тайминги, Room, Robolectric-рендер экранов, серверные на node --test. Собери debug-APK через CI с закоммиченным debug.keystore, приложи файл и ссылку.
